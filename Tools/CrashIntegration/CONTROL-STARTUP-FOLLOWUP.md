## 界面等待

按 OpenAI Docs 的[分层排查指导](https://developers.openai.com/plugins/deploy/troubleshooting)区分客户端、服务和工具调用，再核对本机实现与实际时间记录。安装的 `computer-use-policy.js` 先读取 App policy，再等待 `createElicitation` 的应用访问确认，之后才调用 AX 界面读取；实际原生操作放在 `withSuspendedTimeout` 中。外层 `timeout_ms` 不是这条完整链路的可靠截止时间。

旧 21 分钟调用附近，Codex 日志在 **22:39:24.577** 记录访问确认的 accept/session 响应，原生 AX 转换在 **22:39:25.001** 开始。当前聊天的会话授权记录包含 `com.okvideomac.stage9.smoke`，不包含新建的 `com.okvideomac.stage9.startup.3`。在新身份上，App 已有屏幕窗口且已完成启动，绑定仍等待，后被守护在 15.1277 秒取消；此后没有继续访问未记录授权的新身份。原生服务后续采样处于正常事件等待。这些证据定位了首次 App 授权等待这一来源；旧 accept 日志没有 App ID，缺少完整原请求跟踪，不能把全部 1305 秒都精确分配给这一阶段。

流程修正为：固定使用本聊天已授权的原烟测身份，调用前只读检查当前会话授权；未记录或格式未知时先停止这条 GUI 流程，不能自行授权或复制其他聊天的权限。全局授权未由预检求值，最终权限仍由 CUA 正常机制执行。新身份只做用户已授权的 CLI 启动测量，不换名规避原生访问确认。

真实挂起测试还证明了另一条等待边界：独立守护暂停临时 App 20 秒并保证恢复，JS Promise 在 **5.008 秒** 返回截止错误，但工具在 **11.6687 秒** 才结束，仍受未完成原生调用影响。因此不把 Promise.race 当作完整修复。

新增任务内核守护以本聊天打开的唯一文件句柄、完整 VM session 命令和 CUA 父进程链核对归属，只允许中断这个可重建内核。真实阻塞读取在 **7.1557 秒** 结束，早于测试 App 自动恢复约 **10.697 秒**；随后使用官方 `js_reset` 重建会话，已授权身份重新绑定只用 **0.3758 秒**。共享 Sky 服务没有重启。守护仅用于一个明确调用，不能替代所需授权或保证所有外层传输/审批时延；第一次初始化仍遵守工具入口规则。

恢复后 **5 轮**历史→设置→高级操作，共 **15 次点击、21 次状态/截图观察**全部通过，整段工具用时 **8.3767 秒**。最后按授权预检再重开原身份，绑定 **0.4553 秒**，设置读取、截图和正常 Quit 整段 **1.2904 秒**，App 退出码 0。共享关闭、过滤报告 0，历史精确保持第 2 集 98.41666666666667/128 秒。当前流程已能区分授权等待与原生读取阻塞，并具备经实测的任务范围恢复；没有声称修补了 Codex 的底层产品代码。

## 首次未见窗口

控制恢复验证通过后，针对相同编译代码运行 **6 个全新业务目录**和 **3 个全新临时身份的首次启动**。所有 9 次均出现屏幕窗口并创建 0600 捕获文件。六次目录启动为 0.412726、0.317913、0.317489、0.327900、0.328298、0.328101 秒，中位数 **0.328000 秒**；三次新身份首次启动为 **1.537120、1.495871、1.488304 秒**。每个临时身份严格签名通过，App 编译 UUID 不变，正式原包未修改。新身份首次启动单独报告，不混入既有五轮资源门槛，也不称为冷缓存测试。

原 `window-probe` 只统计 OnScreenOnly、layer 0 且尺寸超过 200 的窗口。它的 0 只能证明当前屏幕没有匹配窗口，不能独自判定根本没有创建窗口。新增被动探针记录同一 PID 的全部大窗口与 on-screen 数量，以及 active/hidden/finished-launching 状态；不注入输入或激活窗口。它仍不能证明原那次已有隐藏主窗。

原第一轮结果/日志在重试时被覆盖，也没有原始堆栈采样，因此无法追溯确定 20 秒异常的原因。本轮不改写产品实现来猜测修复。新的排查夹具每次使用独立目录和日志、禁止直接重跑覆盖结果；20 秒未见窗口时先保存窗口序列、进程信息和 sample，再保持进程供诊断。九个测量进程结束使用确定 PID 的 SIGTERM，不能算作九次原生正常退出。

新身份 GUI 绑定遇到授权等待后，已停止该额外界面验证，回到已授权原身份完成最后的真实主窗与诊断 UI 核验。正式 bundle ID 准入、冷缓存启动和原 20 秒异常的根因仍不计为通过。
